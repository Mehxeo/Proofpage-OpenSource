Proofpage privacy

Updated November 12, 2026 · Maintained by Utsav Das

Your workspace

Proofpage stores your library, revisions, reviewed context and settings on your computer. Collection contacts the sources you choose. For eligible sources other than Google Docs, optional model requests send selected content to the endpoint you configure, only when you request assistance. Optional timestamp anchoring sends a digest. Update checks contact GitHub. The homepage has no analytics or signup form.

Google Docs availability

Shared Google sign-in is awaiting Google's approval of the read-only Docs permission. The local-only AI and sharing safeguards below are implemented in the upcoming 0.5.1 review source; they are not retroactively installed in public 0.5.0. Until the verified update is released, do not send Google Docs snapshots from older builds to model endpoints, MCP clients or exported assistant packs. Current stable users still need their own Google client configuration. We will identify the verified release on the download page when available.

Google user data we access and store

The optional connector requests https://www.googleapis.com/auth/documents.readonly. Google's read-only grant covers documents in the connected account; Proofpage calls documents.get only for document IDs you explicitly select after confirming owner permission. It receives the selected document's title, ID, revision metadata, tabs and returned document structure, preserves the returned API JSON, and extracts body and table text across tabs into the local workspace. It does not list your Drive, read Gmail, change Docs, or scan documents you did not select. Images, comments and suggested edits are not included in extracted text.

OAuth access and refresh tokens stay in your operating system credential vault, separately from the workspace database and its backups. Supported backends are macOS Keychain, Windows Credential Locker and Linux Secret Service. The connector refuses plaintext-token fallback. Bundled native OAuth app configuration identifies Proofpage; it is not your account authorization. Personal tokens are never bundled or committed to source.

How Google data is used

Google API data provides the local document reader, revision history, reviewed local business context, and optional offline extraction, change summaries or passage checks. Google Docs AI processing runs inside Proofpage using a GGUF model file already on your computer and the optional local inference runtime. It performs inference only, without training or updating model weights. Without that runtime and a configured model, these AI actions are unavailable; reading and reviewing documents still work.

Proofpage does not send Google Workspace raw, aggregated, de-identified or derived data to a third-party AI provider, aggregator, hosted model, localhost model gateway or Proofpage server. Google snapshots and their tracked derivatives are excluded from MCP responses, portable assistant context packs, portable evidence exports and training datasets. Existing saved artifacts with Google provenance are checked as well as new imports. These restrictions apply to local stdio and remote HTTP assistant connections. They do not stop you manually copying material outside Proofpage; you remain responsible for copies you make.

No third-party AI provider plan, API tier, zero-retention setting or provider consent is used to process Google Docs in this release. The connector does not use Google data, including derived or de-identified data, to develop, improve or train foundational, shared or generalized AI/ML models. It does not sell Google data or use it for advertising, creditworthiness or lending decisions.

Proofpage's use of information received from Google Workspace APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Protecting sensitive data

Requests to Google's authorization, token and Docs API endpoints use HTTPS. Authorization uses PKCE and an ephemeral loopback callback on your computer. The local workspace API requires a session token and checks origin and host. The SQLite database has owner-only file permissions. Source text is treated as untrusted evidence; approvals remain explicit and model results remain unreviewed.

Tokens are protected by the OS credential vault. The workspace database and its backups are not encrypted by Proofpage. Use your operating system's disk encryption and protect local accounts and backups. Backups can contain document text and the workspace's receipt-signing key, so keep them private. Proofpage's maintainer has no automatic access to local documents. Remove private text and tokens from any support material you choose to send.

Disconnect, retain and remove

Disconnect in Business context to remove local Google authorization and pause document schedules. You can also revoke the grant in Google Account connections. Disconnecting retains imported evidence; you control its retention. To remove the entire local workspace, quit Proofpage and delete the Proofpage/data folder in your user folder, together with backups or older exported packs you wish to remove. This permanently removes that library and its receipt-signing key. Copies already shared with other services must be removed there separately.

Browser companion

The optional companion has a separate privacy policy. It transfers reviewed content to your paired local app.
